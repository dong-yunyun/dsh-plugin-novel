# 压测暴露问题的修复记录

> 368 章压测（`docs/scale-report.md`）暴露了两个设计问题 + 一个稳定性问题，本轮全部修掉。

---

## ① 概要全书超预算 → 按档位裁剪 + 预算收敛

**问题**：368 章的投影型概要 17,955 token，standard 档预算 6,000，超 3 倍。

**修法**（`buildSynopsis` 重写）：

| 段 | 策略 |
|---|---|
| C 人物谱 | 按出场章数排序，按档位截断，超出标"另有 N 位省略" |
| D 剧情脉络 | 章节数超上限时，只留**高密度章**（按 density 排序）+ **最近 5 章**，标省略数 |
| E 伏笔账本 | 按章号**倒序**（最近的更可能相关），按档位截断，标省略数 |
| 收敛 | 生成后若超预算，三类上限**各自减半**重排，最多 6 轮 |

**实测（368 章）**：

| 档位 | 修复前 | 修复后 | 预算 |
|---|---|---|---|
| compact | — | **1,249** | 2,000 |
| standard | 17,955 | **3,047** | 6,000 |
| full | — | **11,398** | 20,000 |

三档全部收敛到预算内。

**副作用**：31 章真实语料的 standard 概要从 3,323 → 3,112 token（少了 211），因为 D 段按密度挑选后略去了部分过渡章。信息损失可接受，且省略处有明示。

---

## ② 伏笔账本线性膨胀 → 倒序 + 档位截断

**问题**：每章 2 条新伏笔、少有人标回收 → 368 章累积 **736 条**未回收。概要把它们全列出来毫无意义。

**修法**：

- 概要不全列，按档位只取**最近 N 条**（compact 8 / standard 20 / full 60）
- 其余显式标"另有 N 条较早的未回收伏笔省略"
- 排序改按章号倒序——越近的越可能与当前续写相关

**没有改**的：`bible.json` 仍保留全部伏笔（数据不该丢），只是在概要视图里做投影截断。

---

## ③ 长章抽取失败 → 分段抽取 + 合并

**问题**：ch84（6,194 字）单次调用连续失败两次——输出预算被 reasoning 吃光，返回空文本。

**修法**（`splitForExtraction` + `mergePartCards`）：

```
6194 字 → 按段落边界切成 2 段（3768 + 2425）
       → 每段独立抽取，提示里标"第 N/M 段"
       → 合并：beats 按序拼接截 6 条，实体/关系/状态/物品/揭露去重，
               location/pov 取并集，hook 取末段，density 由合并结果重算
```

**离线验证**：

| 检查 | 结果 |
|---|---|
| 切段长度 | 3768 / 2425，均未越界 |
| beats 合并 | 4 条，保序 |
| 关系去重 | 2 段重复的同一关系 → 1 条 |
| 状态去重 | 按 `subject|field|to` 去重，不同的保留 |
| location | 并集 |
| hook | 取末段 |
| density | 重算（0.76） |

**注意**：这个改动在 `index.js` 里，**未触发热重载**（按你的隔离要求），下次 DSH 自然重启后生效。合并逻辑本身已在离线验证通过。

## ④ 附：4 条"未解析伏笔"查清了，是 schema 被误用

原先以为是匹配算法不够好，逐条查完发现**根本不是引用**：

| 章 | 标签 | 实际是什么 |
|---|---|---|
| 7 | 彭风拉拢方少云做枪手的用意 | 动机描述 |
| 13 | 方少云的腿伤（前章受伤）在此成了挨打的直接原因 | 因果描述 |
| 15 | 一个月前方少云在 Luna 上惨败 Lulu 的旧账 | 背景描述 |
| 29 | 野人、二少等人莫名输给湖大校队的原因 | 这条**确实是**回收（对应 F-18-1「湖大校队实力成谜」），只是写成了整句 |

前三条是模型把本章自身的因果/动机塞进了 `paid` 字段——**那是 `beats` 或 `state_changes.cause` 该待的地方**。

修法两条：

1. **抽取 prompt 加约束**：`paid` 只能填前面章节已埋伏笔的原话，没有真回收就留空。
2. **概要显式披露**：E 段加一行「另有 N 条回收标注无法对应到具体伏笔，未计入已回收」，而不是静默丢弃。

现在概要 E 段长这样：

```
未回收 64 条（列出最近 20 条）：
- …
- （另有 44 条较早的未回收伏笔省略）
已回收 2 条。
另有 4 条回收标注无法对应到具体伏笔，未计入已回收。
```

**没做的事**：没有为了"消灭这 4 条"去放宽匹配阈值——那会引入假阳性（之前 0.12 阈值就误配过 2 条）。**宁可如实说"对不上"，也不假装匹配成功。**
