# 续写：主题输入 + 一致性闸门

> 工具：`novel_continue({ topic, avoid?, from?, length? })`

---

## 一、解决的问题

原来的「续写」只给上下文（概要 + 最近 3 章注入态），你拿到的是一堆材料，还得自己写指令。

现在改成：**你给主题，工具先校验，通过才产出可执行的续写简报。**

```
主题 → 与前情状态比对 → 有硬矛盾：拒答并列冲突（不出简报）
                       → 无矛盾：出简报（承接点/目标/必守/禁止/需澄清/篇幅）
```

---

## 二、闸门的判定口径

**只报硬矛盾**，不报软问题：

| 算硬矛盾 | 不算 |
|---|---|
| 已死亡/已退场角色再次出场 | "这样写读者可能不喜欢" |
| 已淘汰选手在同一赛事复活 | "主角赢太快不合理" |
| 已知重伤状态下做超限动作 | "可能有点难写" |
| 与已揭示事实直接相反 | 主题存在歧义（写进「需澄清」） |

歧义不拦——这是刻意的。你那句「后续比赛」本身没说清是足球还是星际，闸门不该卡在这里，而应把它变成简报里的一个问题。

---

## 三、两个实测

### ① 放行案例

```
novel_continue({ topic: "后续比赛：方少云战绩一般，不详写对战细节", length: 2000 })
→ status: "ok"
```

产出的简报（节选）：

| 项 | 内容 |
|---|---|
| 承接 | 第 84 章赛后——方少云 2:1 逆转 CX_teacher 晋级败者组九人，苟小云抽走唯一轮空 |
| 目标 | 用侧写呈现战绩平平，笔墨放在心理落差、苟小云点评、Lulu/Kay 态度变化、败者组「输一场就回家」的压迫感 |
| 禁止 | 详写战术与操作细节；让方少云打出不符成长线的统治级表现；让苟小云本轮登场；公开师徒关系 |
| 需澄清 | 「战绩一般」是勉强取胜后被淘汰，还是中途落败出局？ |

**这正是你要的效果**：主题进了指令，「不详写对战细节」被落成一条明确的禁止项，而不是靠模型自觉。

### ② 拦截案例

```
novel_continue({ topic: "已淘汰的 CX_teacher 再次出场，把方少云淘汰出局复仇" })
→ status: "conflict", blocked: true
```

```
冲突：CX_teacher 已在第 84 章败者组被方少云 2:1 淘汰出局，按败者组赛制
     输一场即退场，无法在同一 CPL 赛事中再次出场。
依据：第84章：败者组对阵 CX_teacher……2:1 取胜晋级；方少云晋级败者组九人，
     CX_teacher 已被淘汰。
建议：改写为其他赛事（分站赛/线下挑战赛/回访交流赛），或换一名尚未淘汰的对手。
```

**没有生成简报**——这就是"判断与前文关联之后才能执行"。

### ③ 一次失败的测试（记录在此，避免误判）

我最初拿「苟小云本轮出战击败纳兰容容」当矛盾测试，闸门放行了。复查原文：苟小云抽走的是**本轮**轮空，下一轮本来就该他上——**闸门是对的，我的测试题错了**。

这条要留着：验证一个人工闸门时，得先确认测试题本身真的矛盾。

---

## 四、成本与边界

| 项 | 说明 |
|---|---|
| 模型调用 | 每次请求 1 次（输入≈前情状态+近 3 章，输出≈简报） |
| 不生成正文 | 工具只出简报，正文仍由对话里的模型按简报写 |
| 依赖 | 需要已抽取卡片；无卡片时直接报错 |

**为什么不在工具里直接写正文**：正文应当在主对话里写，这样你能中途插话改方向；工具若一次吐 2000 字，等于把控制权交出去了。

---

## 五、建议用法

```
1. novel_continue({ topic: "...", length: 2000 })
2. 看 brief.需澄清 —— 那几个问题往往正是你没想清楚的地方
3. 按 brief 写；若 status=conflict，按 conflicts 里给的改法调整主题再调
```
