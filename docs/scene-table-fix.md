# 场次表错位修复记录

> 报告来源：用户指出第 2、7、8、9 章的「地点」「人物」列错位，并要求对原文核对。
> 结论：**是我投影代码的 bug，不是模型抽错。已修复，并逐章对过原文。**

## 一、根因（两个，都在 `buildScreenplay`）

**① 地点用了位置钳位**

```js
place: location[Math.min(i, locations.length - 1)]
```

一章有两个地点时，第 2 条 beat 之后全被塞成「最后一个地点」。所以第 2 章的课堂、食堂都被标成「生命网吧」——因为 `location = [中南大学, 生命网吧]`，钳位后 i≥1 全是后者。

**② 人物栏没过滤实体类型**

`entities_new` 里 `kind: place/org` 的条目（生命网吧、学生三食堂、BOS网吧）被当成人物并列进去。

---

## 二、修法：不再猜，改读原文

第一版修法是把地点改成「按 beat 文本匹配，匹配不到标（待确认）」——**结果满屏待确认**。因为 beat 是模型概括过的句子，"上课"里不含"中南大学"三个字，文本匹配根本命中不了。

所以最终方案是加一个富化工具 `novel_scenes`：

| 步骤 | 工具 | 做什么 |
|---|---|---|
| 1 | `novel_ingest` | 抽卡片（事件级） |
| 2 | **`novel_scenes`（新增）** | 读原文，按连续时空拆场次，落到 `scenes/chNNNN.json` |
| 3 | `novel_synopsis(profile=screenplay)` | 优先用富化场次；没有才退回卡片投影 |

场次表新增**「来源」列**：`原文` = 模型读原文拆的，`卡片` = 从 beat 投影的。**两种来源一眼可辨，不会再混。**

人物栏现在只取 `kind: person` 的实体与关系端点，并剔除全书已知的场所/组织名。

## 四、仍然存在的问题

**模型拆场会漏掉章首/章末的短场。** 第 2 章丢"起床"，第 8 章丢"破单车训练"。

这两场都短、都在章的两端，属于典型的注意力边缘。修法候选：

1. 在 prompt 里显式要求"必须覆盖全章，包括开头与结尾"
2. 加校验：拆出的场次总字数应接近章字数（现在没法算）
3. 加一个"章首/章末各至少一场"的硬约束

第 3 条最可控，下次改 prompt 时一起做。
